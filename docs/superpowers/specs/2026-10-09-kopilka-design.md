# «Копилка» — личный учёт финансов с лимитами по категориям

Дата: 2026-10-09 · Статус: черновик на ревью · Платформа: iOS 17+, SwiftUI + SwiftData

## 1. Зачем

Владелец получает зарплату на карту Halyk, но не может накопить и не понимает, куда уходят деньги.
Приложение должно:

1. Показывать, **куда уходят деньги**, без ручного ввода — из выписки банка.
2. Давать **ставить лимиты** по категориям и видеть, **сколько ещё можно потратить до зарплаты**.
3. Не искажать картину перемещениями между своими счетами.

Критерий успеха: после импорта выписки и одного прохода «Проверьте новое» главная цифра
«можно потратить до зарплаты» и лимиты по категориям совпадают с реальностью, а траты не задвоены.

## 2. Что известно из выписки (исходные данные)

Источник анализа — выписка Halyk по текущему счёту «Зарплата», карта `*2936`, период 02.10.2025–09.10.2026,
42 страницы, 1 160 операций. Итоги разбора совпадают со строкой «Всего» до копейки.

- Таблица: `Дата проведения | Дата обработки | Описание | Сумма операции | Валюта | Приход | Расход | Комиссия | № карточки/счета`.
- Описание может занимать несколько строк. В тексте PDF пробелы внутри описания часто пропадают
  (`Переводнадругуюкарту`), поэтому сравнение описаний — **без учёта пробелов и регистра**.
- Шапка содержит: номер счёта, тип счёта, период, дату формирования, входящий/исходящий остаток,
  доступную сумму, заблокированные суммы.
- Комиссия за перевод в другой банк **спрятана в «Расходе»**: `Расход − Сумма операции` = 200 ₸
  (с сентября 2026 — 250 ₸). В колонке «Комиссия» стоит 0. Международные переводы и ежемесячная плата
  за карту (150 ₸) идут в колонке «Комиссия».
- Проценты по депозиту в выписку карты **не попадают** (0 строк) — они начисляются на счёт депозита.
- Покупки по карте идут с января 2026; надёжные данные о движении средств — **с 01.03.2026**.

### Типы операций в выписке и как их понимать

| Описание (без пробелов, начинается с) | Тип в приложении |
|---|---|
| `Операцияоплатыукоммерсанта<ПРОДАВЕЦ>` | расход, категория по продавцу |
| `ПоступлениенасчетТОО"<работодатель>"` | доход «Зарплата» (аванс/зарплата — см. §5.4) |
| `Переводнадругуюкарту` | перевод без получателя — по правилам §5.3 |
| `Переводнадепозит` / `Зачислениесдепозита` | **внутреннее перемещение** карта ↔ депозит |
| `Поступлениеперевода`, `Платежстекущегосчета…безвозмездные` | доход «Переводы от людей» |
| `Поступлениенакарту<ПРОДАВЕЦ>` | возврат — уменьшает траты категории продавца |
| `Погашениебанковскойзадолженности`, `ПереводнакредитRS` | расход «Кредиты» (обязательный) |
| `Оплатакредитав ЖилстройСберБанке` (как оплата у коммерсанта) | расход «Ипотека» (обязательный) |
| `Исходящиймеждународныйперевод` | расход, категория «Не определено» до разметки |
| `Ежемесячнаякомиссия…RegularCharge` | расход «Комиссии банка» |

## 3. Объём версии 1

**Входит:**
- Импорт выписки PDF через «Поделиться» и из приложения; разбор и проверка по итогам.
- Импорт без дублей при повторной загрузке перекрывающихся выписок.
- Начальная настройка: история + остатки «на сейчас» (точка отсчёта).
- Выписка депозита: проценты как доход, склейка с выпиской карты; «Сверить остаток».
- Автокатегории с обучением на правках.
- Правила перемещений и переводов (депозит, своя Kaspi до даты, жена, рассрочка, комиссии).
- «Проверьте новое»: правка названия и категории, объединение дублей, **без удаления**.
- Три режима периода; обязательные и гибкие категории; цель «Отложить»; лимиты.
- Главная «Можно потратить до зарплаты / до конца месяца».
- Аналитика: темп трат, куда уходят деньги, сколько осталось по месяцам; карточка категории.
- Три темы оформления (A светлая нативная, B тёмная, C тёплая бумажная) + системная тёмная тема.
- Тумблеры источников **Apple Pay** и **SMS** с точками входа для «Команд» и склейкой источников.
- Экспорт и восстановление резервной копии (JSON-файл).

**Не входит (версия 2+):** синхронизация через iCloud (нужен платный аккаунт разработчика),
импорт выписок Kaspi, виджеты, точный разбор SMS (ждём реальные примеры текстов), мультивалютные счета.

## 4. Архитектура

Один таргет приложения + тестовый таргет. Все данные локально, в сеть ничего не уходит.

| Блок | Отвечает за | Зависит от |
|---|---|---|
| `StatementParser` | PDF → `ParsedStatement` (шапка + сырые строки) и сверка с «Всего» | PDFKit |
| `Fingerprint` | ключ строки по исходным полям | — |
| `Importer` | запись строк без дублей, склейка с записями из других источников | Store, Matcher, Classifier |
| `SourceMatcher` | поиск «той же операции» среди записей из других источников | — |
| `Classifier` | категория и название по правилам продавцов и сумм | Store |
| `TransferRules` | внутренние перемещения, жена, рассрочка, комиссии, зарплата/аванс | Settings |
| `PeriodCalculator` | границы периода в трёх режимах | история зарплат |
| `BudgetCalculator` | «можно до зарплаты», остатки лимитов, обязательные | Period, Store |
| `BalanceCalculator` | остатки карты и депозита от точки отсчёта | Store |
| `Intents` | App Intents для «Команд»: Apple Pay, SMS | Importer, Settings |
| `Theme` | токены цвета/шрифта/радиусов трёх тем | — |
| UI | экраны §8 | всё выше |

Логика (`StatementParser` после извлечения текста, `Fingerprint`, `Importer`, `SourceMatcher`,
`Classifier`, `TransferRules`, калькуляторы) — чистые функции над структурами,
без SwiftUI, чтобы тестироваться отдельно.

## 5. Логика

### 5.1. Разбор PDF

1. PDFKit: для каждой страницы взять строки текста с координатами.
2. Найти строку заголовка таблицы, взять **x-границы колонок по положению заголовков**
   (не хардкодить координаты).
3. Новая строка таблицы начинается, когда в первой колонке дата `ДД.ММ.ГГГГ`; строки без даты —
   продолжение описания предыдущей.
4. Числа: `-1 093,00` → `Decimal`. Деньги везде `Decimal`, не `Double`.
5. Из шапки: номер счёта, тип счёта, период, дата формирования, остатки, доступная сумма.
6. **Сверка:** сумма «Приход», «Расход», «Комиссия» должна совпасть со строкой «Всего».
   Не совпало → импорт не записывает ничего и показывает «Выписка разобрана не полностью: расхождение N ₸».
7. Тип выписки по номеру счёта: карта / депозит / неизвестный (предложить создать счёт).

### 5.2. Ключ строки и импорт без дублей

- Все записи хранят **исходник** (неизменяемый) и **пользовательский слой** (название, категория, заметка,
  «проверено»). Ключ считается **только по исходнику**; правки ключ не меняют.
- Базовый ключ = SHA-256 от нормализованных: номер счёта, дата проведения, сумма операции, валюта,
  приход, расход, комиссия, описание (без пробелов, в верхнем регистре). Дата обработки в ключ **не входит**
  (может меняться между выписками для одной операции).
- Полностью одинаковые строки (пример: 11.08.2026 три «Зачисления с депозита» по 10 000) различаются
  порядковым номером: ключ = `базовый#1`, `базовый#2`, … в порядке появления в файле.
- Повторный импорт: для каждого базового ключа в файле `n` вхождений, в базе `m` → добавить `n − m`
  (если `n > m`), остальные пропустить. Отчёт: «Новых 34 · уже было 812».

### 5.3. Переводы и перемещения

1. **Карта ↔ депозит** (`Переводнадепозит`, `Зачислениесдепозита`) — тип «перемещение», не расход и не доход.
   Если загружена выписка депозита, встречная строка (пополнение/снятие той же суммы, дата ±1 день)
   присоединяется к той же записи как второй источник.
2. **Перевод на другую карту** — сумма записи = «Сумма операции»; разница с «Расходом» хранится как
   комиссия записи и в аналитике идёт в «Комиссии банка».
3. Правила для переводов без получателя (применяются по порядку, настраиваются в «Категории и правила»):
   - дата раньше `kaspiOwnCardUntil` (по умолчанию 01.03.2026) → «перемещение на свою Kaspi *3436»;
   - сумма 100 000 или 120 000 в течение 3 дней после зарплаты → «Семья (жена)», обязательная;
   - сумма 54 000 ± 500 в течение 7 дней после аванса → «Рассрочка Kaspi», обязательная;
   - иначе → «Переводы — разобрать», запись не проверена.
   Пользователь может создать своё правило «сумма в диапазоне + окно после события → категория».
   Получателя в выписке нет, поэтому «запоминание по получателю» работает только для SMS (если в SMS он есть).

### 5.4. Зарплата и аванс

- Работодатель задаётся в настройках (по умолчанию — самый частый `ПоступлениенасчетТОО`: «АЦЭПАК»).
- Поступление от работодателя с днём месяца 10–20 → **аванс**, иначе → **зарплата**.
- Разовые крупные поступления (больше 1,5× медианы) — тоже доход «Зарплата», но **не сдвигают границу
  периода** и не участвуют в прогнозе дохода.
- Ожидаемая сумма аванса/зарплаты = медиана последних 3 таких поступлений; ожидаемая дата = медиана дня месяца.

### 5.5. Классификация

Порядок: правила пользователя → встроенные правила (§10) → «Не определено».
Ключ продавца — нормализованное название: верхний регистр, убраны пробелы, точки, `*`, `_`, `-`,
хвосты касс и филиалов (`KASSA\d*`, `SHOPKASSA\d*`, `ASF\d+`, `NSF\d+`, `NF\d+`, цифры).
`MAGNUM.ASF36.` и `MAGNUM.NSF72.KASSA-1.` → `MAGNUM`.
Правка категории/названия в записи создаёт или обновляет правило пользователя для этого ключа продавца
и применяется ко всем **непроверенным** записям с тем же ключом. Проверенные записи не трогаются.

### 5.6. Несколько источников одной операции (выписка, Apple Pay, SMS)

- Запись = одна реальная операция; у неё 1..n **источников** (`statement`, `applePay`, `sms`, `manual`).
- Новый источник сначала ищет совпадение среди записей, **у которых ещё нет источника этого типа**:
  сумма равна точно; время — Apple Pay ↔ SMS до 10 минут, выписка ↔ остальные до 3 дней от даты проведения;
  ключ продавца совпадает или один содержит другой.
- Одно совпадение → присоединить. Несколько → взять ближайшее по времени. Если продавец не совпал,
  но сумма и время совпали → создать запись с пометкой «возможный дубль» и ссылкой на кандидата.
- Если сумма в выписке отличается от суммы из Apple Pay/SMS (валюта, чаевые), запись берёт сумму выписки,
  прежняя видна в истории источников.
- Остатки и лимиты считаются **по записям**, а не по источникам.
- Действие «Это та же операция, что…» объединяет две записи вручную: источники переезжают в одну,
  вторая скрывается (технически сохраняется как `mergedInto`, чтобы её ключи продолжали ловить дубли).

### 5.7. Периоды

Режимы (настройка, по умолчанию — «Зарплатный месяц»):
- **Календарный месяц.**
- **Зарплатный месяц:** от зарплаты до следующей зарплаты.
- **Полмесяца:** аванс → зарплата, зарплата → аванс.

Будущая граница, пока поступления нет, — ожидаемая дата (§5.4). Если поступление пришло раньше или позже,
граница сдвигается по факту.

### 5.8. Бюджет и лимиты

- Категории бывают **обязательные** (ипотека, рассрочка, кредит RS, коммуналка/связь, семья),
  **гибкие**, **доход**, **перемещение**.
- Лимиты задаются **на месяц** для гибких категорий; в режиме «Полмесяца» лимит делится пополам.
- Обязательные: ожидаемая сумма = медиана за последние 3 месяца (можно задать вручную);
  в режиме «Полмесяца» относится к той половине, где обычно списывается.
- **Цель «Отложить»** — сумма в месяц (в «Полмесяца» — пополам).
- Главная цифра:
  `Можно потратить = Доход периода (факт + ожидаемый ещё не пришедший)
   − Σ max(план, факт) по обязательным − Цель − Гибкие траты факт`.
  Подпись: дни до конца периода и `≈ Можно / дни` в день. Отрицательное значение показывается красным
  как «перерасход N».
- Остаток лимита категории = лимит − траты периода (возвраты уменьшают траты).
  Метка темпа = доля прошедших дней периода. Цвет: обычный < 85% (порог настраивается),
  жёлтый ≥ порога, красный > 100%.
- Настройка лимитов показывает план: доход → обязательные → цель → сумма лимитов → не распределено.
  Если распределено больше дохода — полоса красная с суммой превышения.

### 5.9. Остатки и начальная настройка

- **Начальная настройка** (одноразовый экран при первом запуске):
  1. Выбрать PDF истории → импорт с флагом `affectsBalance = false` для всех записей.
  2. Ввести остатки: карта (подставлено «Доступная сумма» из шапки), депозит (вручную).
     Дата точки отсчёта = дата формирования выписки.
  3. Готово. Повторно — только «Настройки → Начать заново» с подтверждением (стирает всё).
- После настройки запись влияет на остаток, если создана после настройки **и** её дата проведения
  ≥ даты точки отсчёта. Старые операции, дозагруженные позже, остаток не меняют.
- `Остаток счёта = остаток в точке отсчёта + Σ влияющих записей по счёту`
  (перемещения: минус на счёте-источнике, плюс на счёте-получателе).
- **Сверить остаток:** ввод фактической суммы → запись-корректировка на разницу:
  для депозита плюс — «Проценты по депозиту» (доход), иначе «Корректировка». В траты и лимиты не входит.
- Выписка депозита: строки начисления вознаграждения → доход «Проценты по депозиту»;
  формат подписи процентов уточняется по первой реальной выписке депозита.

### 5.10. Источники из «Команд»

Два App Intent'а, оба выполняются без открытия приложения:
- **«Записать оплату Apple Pay»** — параметры: продавец, сумма, валюта, карта (из автоматизации «Транзакция»).
- **«Разобрать SMS Halyk»** — параметр: текст SMS (из автоматизации «Сообщение» с отправителем Halyk).
  Разбор по общему шаблону: сумма с валютой, продавец/описание, остаток. Не разобралось →
  запись «не разобрано» с сырым текстом в «Проверьте новое».
- Тумблер источника выключен → Intent возвращает пустой результат и ничего не пишет.
- Тумблер «Показывать остаток после оплаты» (по умолчанию выкл.): Intent возвращает строку
  «Кафе: осталось 4 200 из 30 000» **только** если категория достигла порога; иначе пусто
  (команда показывает результат, только если он не пустой).
- В настройках — инструкции по созданию обеих автоматизаций.

## 6. Модель данных (SwiftData)

- `Account` — id, вид (карта/депозит/другая своя карта), название, номер, остаток и дата точки отсчёта.
- `Operation` — id, дата, тип (расход/доход/перемещение/корректировка), сумма `Decimal` (KZT, > 0),
  комиссия, счёт, встречный счёт?, **название**, **категория**, **заметка**, **проверено**,
  `possibleDuplicateOf?`, `mergedInto?`, `affectsBalance`, `createdAt`.
- `SourceRecord` (неизменяемый) — id, operation, вид источника, ключ (уникальный), дата проведения,
  дата обработки, сырое описание, сумма операции, валюта, приход, расход, комиссия, сырой текст (SMS),
  время получения.
- `Category` — id, название, иконка, вид (обязательная/гибкая/доход/перемещение), лимит в месяц?,
  ожидаемая сумма?, порог предупреждения, порядок.
- `MerchantRule` — ключ продавца, категория, название?, происхождение (встроенное/пользователя).
- `AmountRule` — диапазон суммы, событие (зарплата/аванс/нет), окно в днях, дата «до», категория/счёт.
- `Settings` — тема, режим периода, работодатель, `kaspiOwnCardUntil`, тумблеры источников,
  «показывать остаток после оплаты», цель «Отложить», признак завершённой настройки.

## 7. Обработка ошибок

- PDF не Halyk / не распознана таблица → «Это не похоже на выписку Halyk», ничего не записано.
- Не сошлось с «Всего» → ничего не записано, показано расхождение.
- Неизвестный счёт → предложить создать (карта/депозит/другая своя карта) или отменить.
- Импорт атомарный: либо вся выписка, либо ничего.
- Intent при ошибке разбора не падает, а пишет «не разобрано».

## 8. Экраны

Вкладки: **Главная · Журнал · Аналитика · Настройки**.

- **Главная:** переключатель режима периода; «Можно потратить до зарплаты/до конца месяца»
  (крупно), дни и «≈ в день»; полоса «обязательные / отложено / потрачено / свободно»;
  остатки карты и депозита; 4 главных лимита с меткой темпа + «Все лимиты»;
  плашка «Проверьте новое · N» (только если N > 0).
- **Проверьте новое:** список непроверенных; в строке — подставленная категория;
  правка названия/категории; «Объединить» для возможных дублей; «Всё ок → в журнал».
- **Журнал:** все записи по дням, поиск, фильтр по категории/счёту/источнику; карточка записи с историей
  источников и действием «Это та же операция, что…».
- **Аналитика** (в выбранном периоде):
  1. Темп: накопленные траты против линии плана; обязательные отмечены отдельно, чтобы скачок 15-го был понятен.
  2. Куда уходят деньги: горизонтальные полосы по категориям по убыванию; тап → продавцы категории.
  3. Сколько осталось: доход минус траты по месяцам (плюс — синий, минус — красный).
- **Лимиты:** план дохода; цель «Отложить»; обязательные; гибкие со средним за 6 месяцев.
- **Карточка категории:** столбики за 6 периодов с пунктиром лимита; лимит крупно; ползунок;
  кнопки «Как обычно / −20% / −40%»; «Экономия ≈ N в период · M в год»; порог предупреждения.
- **Настройки:** тема (A/B/C), режим периода, работодатель, источники (Apple Pay, SMS) + инструкции,
  «Показывать остаток после оплаты», правила и категории, «Сверить остаток», экспорт/восстановление,
  «Начать заново».
- **Начальная настройка:** 3 шага (§5.9).
- **Поделиться → приложение:** приложение регистрируется как открывающее PDF; при открытии файла
  сразу импорт и экран-итог «Добавлено N · уже было M · на проверку K» с кнопкой в «Проверьте новое».

## 9. Оформление

Три темы как наборы токенов (фон, карточка, текст, вторичный текст, дорожка, акцент, ок/внимание/превышение,
шрифт главной цифры, радиус). По умолчанию A. Каждая тема имеет светлый и тёмный вариант по системной
настройке. Диаграммы — Swift Charts; цвета категорий в фиксированном порядке, «превышение» — только статусным
красным с подписью, не только цветом.

## 12. Сборка и установка

Нативный проект Xcode, бесплатный Apple ID (личная команда): переподпись раз в 7 дней с Mac
или автоматически через SideStore/AltStore. App Groups и iCloud не используются, поэтому всё работает
на бесплатном аккаунте. Переход на платный аккаунт не требует изменений кода.
